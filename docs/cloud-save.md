# 同名跨设备存档

用户已明确授权将玩家名字对应的本游戏武器、词条、装备栏、通关进度保存在当前游戏 Netlify 站点的 Netlify Blobs。无其他浏览器数据、IP、用户代理或排行榜数据写入此存档。

## 使用

1. 更新上线后，在原电脑、原浏览器用原来的玩家名字进入游戏，等待显示“已同步”。旧本机装备与进度会自动上传。
2. 手机使用完全相同的名字进入，自动下载并合并。每次打开整军备战或校场页面、主线或校场结算时都会自动同步；停留在整备页面且页面可见时，每30秒检查一次其他设备的改动。
3. 拾取、熔炼、换装和通关后约1秒自动上传。战斗中只上传，不下载或合并装备。
4. 备战界面状态显示“同步中…”、“已同步 · 刚刚／N分钟前”或“已保存在本机 · 稍后自动重试”。状态后的小“↻”按钮仅作为网络异常时的手动备用；失去网络仍能玩并保存在本机，恢复网络后自动重试。

同名账号请不要在两台设备上同时熔炼同一批武器。

旧存档此前从未上传服务器，因此首次迁移必须让保存原档的浏览器至少打开新版一次。单凭排行榜无法重建原武器。

## 实现

- `/api/profile`：GET按名字读取；POST使用ETag条件写入当前合并存档，再备份不可变快照。
- Netlify Blobs store：`wumingzhibei-profiles`，账号路径由名字SHA-256生成，保持与排行榜存储分离。
- 使用现有Netlify服务，不引入第三方存储或新密钥；Blobs客户端锁定10.7.13，以支持条件写入，同时提交依赖锁文件。
- `js/cloud_merge.js` 为共用合并逻辑，`js/equipment_rules.js` 为共用50把容量与熔炼规则。首次读取旧档时合并各标签页最新快照；首次写入建立current记录，原快照不删除。后续在current记录上以ETag重试条件写入，防止并发突破50把。
- 武器按UID并集；同UID修改比较记录时间；各装备槽分别记录修改时间；章节通关与已玩过状态取并集。
- 重铸与丢弃记录永久删除标记。删除记录胜过旧装备，旧设备不能把被消耗武器重新上传复活。
- 原本机v1存档不删除；首次合并前备份v2在 `wzb-equipment-v2-backup:名字`。
- 新设备未出征前的默认赠送装备不会重复加入已有云仓库；两端实际获得的实例均保留。
- 同步请求串行执行；拾取、锁定、换装、重铸、丢弃、已游玩与通关变化后延迟1秒上传。整备页可见时每30秒下载一次，主线和校场结算各下载一次。
- 战斗中不下载、不应用迟到的云端装备变更，避免手持武器突然变化。下次进入整备页或结算时再合并。
- 上传失败不删除本机存档；请求有12秒超时，联网后重试，定时重试间隔15秒。
- 开发者模式不上传，和正式云存档隔离。

## 边界

- 按用户确定的“同名字共用”规则实现，没有额外登录凭据；名字相同即指向同一份存档。
- 这是合并式同步，不提供多人同时重铸同一批材料的事务锁；请避免同名账号两台设备同时消耗装备。
- 在功能部署前，只打开旧网站不会发生云同步。是否上线与是否真机验证必须单独报告。

## 容量约束

前端新增/发放武器与服务端入参、合并结果均限制50把（包含已装备）。不同设备合并超过50把时拒绝该次写入并保留原档，不截断或自动丢弃；提示先在原设备整理再同步。条件写冲突最多重试6次。
